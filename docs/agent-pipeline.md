# One-button builder scaffold (Issue #4)

Historical Assignment 001 baseline. Assignment 002 source generation, Actions execution and current operational limits are documented in [the updated pipeline](assignment-002/README.md).

The default static configuration is **unavailable**. Supported local changes run instantly with **Try It**, without a queue, model, adult approval or GitHub step. Unsupported requests say “Needs builder”; no job ID/status is fabricated. The new-game Create input also has Try It; its existing wizard can still save a private idea without claiming it is playable. Development/GitHub/copy-brief controls are restricted to the parent page.

## Implemented reference pipeline

- `server/openapi.json`: versioned private job, revision, preview, keep/undo and catalog contracts. `/v1/jobs` is the canonical queued-build API from the newer Issue #4 contract; the older charter `/v1/generations` declarations remain proposed types, not a second active endpoint.
- `server/pipeline/auth.ts`: HMAC-signed session verification, expiration and role/family scope. A trusted parent-managed identity provider must issue these HttpOnly Secure SameSite host-only cookies; there is deliberately no anonymous session-minting endpoint. Origin allowlist, JSON-only POST and custom CSRF header are enforced by the HTTP adapter. Session/preview signing keys stay server-side.
- `JobService`: typed `draft → queued → building → testing → ready`, terminal failure/cancel, bounded retry (two by default), timeout, family idempotency with conflicting-payload rejection, per-family request throttling, audit transitions without prompts, and immutable candidate revisions. Failed/cancelled builds never update the kept revision pointer.
- Spending is off by default. Only a parent session can enable/set an allowance. Reservations occur in the same repository transaction as enqueue; concurrent submissions cannot overspend. Usage settles after testing; cancellation/failure conservatively consumes the reservation, never refunds unknown provider usage. Limits fail closed when repository operations fail. The unit tests use an injected fake metered adapter to prove cutoff behavior; no actual paid adapter is enabled.
- `Repository` is a transactional port for Firestore. Memory implementation is test-only; `FileRepository` provides atomic private local persistence for a **single process** and recovery tests. Queued work survives reopening; interrupted building/testing jobs fail with `WORKER_RESTARTED` and can be retried within policy. It is not a cloud/distributed queue implementation. Production needs Firestore transactions, worker leases, durable scheduling, retention/deletion and operational monitoring.
- `AgentAdapter` gets a manifest, private base revision, child intent, capability allowlist, abort signal and resource budget, never cloud credentials or repository write access. Availability must be explicit. Real provider/CLI adapters remain disabled; see [research](codex-agent-research.md).
- Candidate artifacts are **closed declarative JSON**, currently only a star-catching game definition. Arbitrary code, extra fields and out-of-range values are rejected. A trusted renderer compiles that declaration to a distinct playable mechanic: tapping stars before a countdown, with win/loss/replay. The CI mock is not an LLM and accepts only a documented star-catching fixture grammar.
- `ArtifactGate` must pass before a revision becomes ready. Browser tests inject a real Chromium gate, play the compiled candidate in an opaque sandbox iframe and assert a win. The service has no permissive default gate. Production must supply independently isolated compile/static/browser testing before serving artifacts.
- Private preview requires an authorized revision lookup, then a short-lived signed capability bound to artifact/family/expiry. Preview uses a distinct hostname, strict CSP (`default-src 'none'`, hashed script, `connect-src 'none'`), no camera/microphone/location, and sandbox `allow-scripts` **without** `allow-same-origin`. The renderer contains no user code or network/storage API. Parent UI validates frame source, nonce and artifact ID before accepting narrow outcome messages. Preview URLs/capabilities are not stored in localStorage or the public repository.
- Children can play, keep, request a revision, retry a failed job, cancel, undo a kept change and reopen a kept game after reload from the private family catalog. No personal credential is embedded in the Vite build. Local game/math/profile saves continue to use their original separate stores.

## Scope and operational limits

No backend, cloud project, database, bucket, queue, paid agent or identity provider is provisioned or running for users. A static Pages deployment stays fully functional for local remixes. A production deployment must provide an explicitly configured HTTPS API and a preview on a different hostname, verified family provisioning and credentials, funded quotas and an isolated worker. The browser loads only nonsecret endpoint configuration from `factory-config.json`; default is unavailable. Test fixtures override this file on a localhost server and label the mock visibly.

Arbitrary generated JS modules remain **unsupported**; the safe declarative candidate demonstrates the new-mechanic path but does not complete a general code-generation sandbox. Original-game fidelity remains pending as described in the gap analysis. Remote kept-game durability is provided by the configured service repository, not exported inside a device-local progress backup; cross-device access requires the same authorized family service. Local profile switching clears preview state; remote authorization is the server's family identity, not an untrusted local profile ID.

Remaining production security work: real identity enrollment/session rotation/revocation, comprehensive content moderation beyond bounded input/PII rules, distributed quota and queue adapters, external worker time/memory/egress enforcement, cloud IAM/storage rules, deletion/retention, real provider integration/smoke tests, and tested release publication/rollback. Static Pages hosting is not a private job queue. Nothing auto-merges or auto-deploys.
