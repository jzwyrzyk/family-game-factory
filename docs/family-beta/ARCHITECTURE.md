## Routing and storage

The private configuration selects HOUSEHOLD (the default for existing deployments) or PRIVATE_FAMILY_BETA. PUBLIC is reserved. Unknown values stop startup. A separate deployment and explicit activation configuration are required for beta. The household continues using its configured workspace, private worker, budgets and existing browser origin.

Each external family receives a random, immutable ID, its own host under the configured workshop domain and its own bounded workspace. A host chooses where authentication takes place. A verified session and a live device in that workspace establish authority. The root welcome host has no family data. Retired hosts and family IDs must never be reassigned. Keeping the same browser schemas on separate origins also isolates service workers, Web Locks, BroadcastChannel, localStorage and IndexedDB. A new origin is mandatory for the private application.

The directory uses one Firestore document per family under an environment-specific collection. Membership and operation records contain no child text. The global policy contains participation switches and a limit. Each monthly counter contains two integers. No platform document contains all families' workspaces. Workspace transactions use the same three-MiB chunked representation and private, content-addressed artifact codec as household. Each artifact cache and object prefix belongs to exactly one workspace. Family and global reservation deltas and the worker's immutable job-owner index commit with the job. A failed transaction cannot consume allowance. In-flight reservations keep their original month until settlement.

## Authorization contracts

A new-family or recovery code contains 256 random bits. Its digest, exact purpose, issue time and 24-hour expiry belong to one family. Resending replaces the digest. Redemption and device enrollment commit together. The adult accepts the current notice and terms and sets the existing salted scrypt parent passphrase. A separate pairing code connects that device to the operator's independent contact check. Pending families cannot play. Additional device invitations retain their existing ten-minute window and require the family passphrase. Host-only Secure, HttpOnly, SameSite=Strict cookies use the __Host- prefix on the beta gateway.

Entry requires a live trusted device, approved guardian, the three current acknowledgments and successful passphrase authorization. Each play receipt identifies its family, guardian, device, session digest, notice versions and time. One admission opens one application document. Internal navigation keeps that document. The server expires play after four hours or thirty idle minutes. Device renewal alone cannot enter play. A material notice update invalidates the receipt. Ending play clears the play grant. Forgetting the device also revokes trust.

The neutral address offers Family login and I have an invitation. A nonsecret workshop code leads to that family's first-party host. No beta service worker or cache-first navigation is installed.
