# Computational Thinking — distinct grade 1–4 benchmark and test plan

**Construct boundary:** computational thinking (CT) is reasoning about sequenced procedures, patterns, conditionals/repetition, representations, decomposition and detecting/fixing logical errors. It is **not** general active problem-solving, app fluency, coding syntax, game complexity, or how elaborate the AI-built artifact appears.

## Standards / evidence
- Research progression: Computer Science Teachers Association (CSTA) Level **1A (K–2)** / **1B (3–5)**, particularly algorithms/programming and data/analysis, and the K–12 Computer Science Framework. Do not reproduce CSTA prose or advertise CSTA-certified alignment without permission and formal review. CSTA content is CC BY-NC-SA 4.0.
- Directly relevant instrument: **TechCheck**, validated ages **5–9 / K–3**, 15 scored unplugged items, six domains, ~13 minutes; instructor/proctor required. Direct access and commercial rights must be requested. Not automatically validated in grade 4 or older ages.
- **cCTt**: peer-reviewed psychometric research involving 575 students in grades 3–4 supports investigation as an external grade 3–4 outcome; the BCTt is more useful at lower ability ranges. Confirm actual access, commercial rights, language, norms and administration restrictions before use.
- **ScratchJr Project Rubric**: validates assessing young children's coded projects, *not* AI-generated program sophistication. Jems must assess child-attributable decisions, not programmatic features generated by an agent.

## Domain subconstructs
| Subconstruct | Child independently does | Unplugged response |
|---|---|---|
| Sequence / algorithm | Order explicit steps to reach an objective, identify missing step | order picture cards |
| Pattern / control structures | Identify repeats, loops, conditions and predict outcomes | predict next move in small grid |
| Decomposition / representation | Break a complex task into smaller parts; translate picture to a workable representation | split task and arrange pieces |
| Debugging / trace | Trace a rule set, locate first error, choose valid correction | mark wrong step and repair |

**Do not count** clicking, prompts written to the AI, final game type or time on platform as CT achievement.

## Grade 1–4 observable anchors
| Grade | Sequence | Patterns/control | Decomposition/representation | Debugging |
|---|---|---|---|---|
| 1 | Arrange 3–5 explicit steps for simple route | Continue short repeat and follow a single rule | Divide one visual goal into 2 simple subgoals | Spot one mismatched action in 3-step trace |
| 2 | Sequence 4–6 steps with fixed goal | Predict outcome of a short repeat/conditional without syntax | Translate a route to symbols and connect 2–3 subgoals | Correct a 4–6-step sequence and show result |
| 3 | Create/trace sequences with nested subgoals | Interpret repeat/if-then with clearly stated conditions | Partition task, choose an efficient reusable subroutine | Identify incorrect assumption; trace consequences |
| 4 | Select algorithm fitting more than one input | Combine repeating rule and condition; identify invariant | Generalize a sequence for multiple configurations | Systematically test options, isolate and correct logical failure |

These grade anchors are **Jems-designed operationalizations** inspired by the CSTA grade bands; CSTA does not itself establish individual grade 1 vs grade 2 or grade 3 vs grade 4 cut scores.

## Independent instrument design
- **Form A and B:** each **16 novel items**: 4 per subconstruct, with one easy, two grade-typical and one transfer-level item in each strand. Additional withheld C for delayed retention. Each correct = 1; incorrect = 0. **16-point uncalibrated raw score, not a CT IQ or standardized percentile**.
- All CT assessment should use **unplugged puzzles** rather than the child's previously created games, to test whether skills transfer outside the interface.
- Grades 1–2: simple illustrated grids/objects; read neutral directions aloud if needed, using exactly the same script at pre/post.
- Grades 3–4: more complex trace/rule puzzles, no programming language prerequisite.
- Standardized nonteaching proctor instructions, two unscored practice examples, no hints, fixed 12–20-minute target (pilot-adjusted), accessible response mode.
- Each item has an objectively verified correct key, item-specific rationale, distractors representing plausible misconceptions, cognitive load review, grade-specific pilot data, source/licensing metadata.
- Presentation format should be balanced: grid navigation, symbol patterns, story procedures. Avoid conflating CT with arithmetic, English reading proficiency or fine motor speed.
- Alternate-form *comparability must be demonstrated*, not asserted from matching slot counts.

## Report
Report score and (n=16) separately by grade and subconstruct (4 items/strand is too sparse for strong individual mastery labels); include uncertainty and descriptive change only until validated. Better external primary study endpoint: licensed TechCheck or cCTt, administered/scored independently, not practice questions authored by Jems.

## Sample items — public examples, never secure tests
1. Grade 1 sequence: Robot must move **right, right, down** from the top left to a star drawn two squares right and one square down. Which three move cards work? Key: R, R, D (equivalent routes accepted only if goal and obstacle rules permit).
2. Grade 2 pattern: “The robot repeats *up, right, up, right*. What is move 7?” Key: up.
3. Grade 3 conditional trace: “If the light is red, stop; otherwise move one square. Red, green, green: how many squares?” Key: 2. This is 1 rule and 3 inputs, not a language comprehension test.
4. Grade 4 debugging: “A program intends to visit (1,0) then (1,1) from (0,0). Instructions: right, right, up. Which single step should change?” Key: second right -> a nonmovement/other valid sequence must be specified. **Authoring caution:** this example has no single-edit repair under the original three-command length if all three commands must be directional moves; reject it as an item. Its presence demonstrates the need for mechanical item-oracle testing.

## Validation and governance
- Check external construct alignment with independent CT/CS educator; run response-process interviews; trial psychometric properties on multiple grades.
- For internal puzzles measure reliability, test-retest when no intervention, item difficulty, distractor effectiveness, floor/ceiling, subgroup bias and equivalent A/B difficulty.
- After external license: lock secure instruments outside public repository/frontend, adhere to proctor and no-modification conditions.
- Do not mix scores with active problem-solving: a child's CT can improve while design-testing skill remains unchanged.
- Do not award extra credit for generating an advanced game using AI; use child-originated plans/traces **only as formative process evidence**.
