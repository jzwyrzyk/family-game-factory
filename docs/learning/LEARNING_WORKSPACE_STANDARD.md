# Jems learning workspace

A child should be able to try an idea, change it, check their work and get back to the game. The trusted host presents one activity from the family's selected subject. The largest element should be what the child reads, studies or changes. The question, controls, feedback and return action belong to that activity for its entire lifetime.

## Design references

Use Khan Academy Kids for warmth and ease of entry, DreamBox for mathematical exploration, the Math Learning Center for manipulable representations and Teach Your Monster to Read for playful literacy. Within Jems, compare the active workspace with the Gem Factory's focal objects, My Powers' readable surfaces and the Creation Studio's reachable tools. Preserve current Jems artwork, typography and icon treatments. The earlier screenshots are a dated baseline. [Child interface](../brand/CHILD_INTERFACE.md) · [Brand library](../brand/LIBRARY_V1_2.md) · [Learning readability captures](../brand/previews/learning-readability-20261120/README.md)

Use a warm light surface with dark ink in both subjects. Purple and blue identify Math, mint and coral identify English. Color accompanies shape, labels, focus or selection marks. Use the existing brand tokens and pair foregrounds with the actual rendered backdrop. Keep the question as the heading. A primary action checks a constructed answer. An unambiguous single choice may submit on tap. A visible speaker reads the allowed content. Feedback occupies a stable, readable place near the work. Place help, optional tools and Pal art around the task without displacing it.

Ordinary labels require 18 CSS px, main instructions generally 20 px and question headings at least 22 px. Secondary controls need 44 px touch targets, visible keyboard focus and meaningful names. Verify 4.5:1 contrast for normal text and 3:1 for meaningful non-text boundaries and states. Inspect the effective text size inside scaled illustrations. Provide a tap or keyboard path for every drag interaction and expose the current selection programmatically. Honor reduced motion. Read error and help states at narrow widths and under zoom.

Allow one natural scroll direction through long tasks. In fullscreen the trusted learning host owns the available space. Keep the question present when showing a passage, model or working surface. Fold secondary tools on short/narrow screens. Preserve edits across reflow, tool disclosure and input-mode changes. Entry focus belongs on the question. Deliberate answer entry may open the device keyboard. Return focus through the host's actual continuation or exit.

## Attempt and assistance contract

The host owns the grade ceiling, selected subject, question budget, pause/resume, provenance and profile. The subject engine selects and evaluates the item, updates the existing attempt, persists evidence and handles rewards through the existing saved-source path. The presentation owns transient edits and reports only the existing answer, help, delivery and completion events. It must never award gems, create a second attempt on switching tools or infer learning from a gesture. [Math integration](../adaptive-math/integration.md) · [English integration](../adaptive-language/integration.md) · [Rewards](../rewards/README.md)

| Event | Effect on the existing attempt |
| --- | --- |
| Inspect a given, mark a location, move counters, rearrange a tile, erase a sketch, change screen orientation | Continue the same attempt. No response or credit for the edit. Record the actual representation where the subject contract distinguishes visual construction. |
| Submit an answer | Pass the authored choice value, numeric/fraction string, ordered tokens or edited text to the subject evaluator. Empty or malformed input follows the engine's validation rules. |
| First valid correct response | The subject engine determines independence from the actual representation, prior answers, hint depth and applicable speech or grown-up assistance. |
| Wrong response followed by revision | Retain the recorded response and editable work where appropriate. A later correct response contributes supported evidence. Respect the optional Math challenge consequence. |
| Reveal a hint | Record the level before displaying it. Draw attention to a given, illustrate a technique, then explain the next reasoning step. Use reviewed item hints. |
| Reveal the worked solution | Record the worked-example level first. Continue through the existing shown outcome. Earlier responses and help remain visible to reporting. |
| Play audio | Math wording is an access accommodation. Early prompts use the device-only delivery path. Declared grown-up prompt reading counts as support. A neutral English direction can be heard independently. Hearing assessed text through Read with me counts as listening support when playback actually starts. |
| Submit creative writing | A nonempty child-authored response is a saved exploration. Closed grammar/editing tasks use their authored evaluator. |
| Leave or switch profile | Dispose transient work, pending callbacks, audio, timers and listeners. The existing host records interruption and applies its unanswered-receipt policy. |

Use equivalent fraction and decimal answers only where the engine permits them. A child who constructs a quantity can demonstrate visual reasoning. A solver, preselected answer, ready-made equivalent fraction, sum, revealing default, image name or automatically highlighted evidence can invalidate the task. Audit visible text, SVG titles, alt text, accessible names, speech payloads, sample answers and initial control values. In a question asking for a chart's greatest value, a screen reader may describe each bar and its value, while identifying the winning bar would perform the comparison. Treat supported and independent observations separately in parent reports. Keep sensitive child writing in its established profile scope. ## Math capability matrix

The application chooses a model from the item’s skill, authored operation, visual and answer kind. A construction can supply an answer. An exploration keeps the original answer field or choices. Unmapped items retain their normal answer route. Subject controllers apply the host’s allowed mode. An authored visual checkpoint can offer its matching model. Symbolic checkpoints can open a model through the recorded hint pathway. [Model selection](../../src/learning/workspace/math.ts) · [Construction models](../../src/learning/workspace/math-construction.ts) · [Measurement and data models](../../src/learning/workspace/math-measure.ts) · [Shape inspection](../../src/learning/workspace/math-geometry.ts) · [Curriculum](../adaptive-math/curriculum.md)

| Implemented family and routing | Available interaction | Response and assistance boundary |
| --- | --- | --- |
| Pre-K/K counting, numeral/set matching, classification, patterns, simple joining and subtracting | Existing pictured sets, tap-each, subset selection, quantity building, pattern and shape choices. Empty groups have an explicit representation. | The original early renderer submits a count, choice value or exact selected subset. Theme substitutions apply only to interchangeable objects. |
| Grade 1 addition within 10/20 and missing addends | Single or double ten-frame. Children add, remove or move their own counters by pointer or tap. Given counters remain fixed. | Submit the number added. Choosing zero is an intentional response. |
| Grade 1 equality and Grade 2 even/odd | Move counters between two groups by tapping or dragging. Equality permits adding/removing counters. Parity preserves the given collection. Empty groups remain usable. | The arrangement is exploratory. Submit the original relation or parity response. |
| Grade 1 subtraction within 10/20 and Grade 3 fraction-number | A marked line with ticks, recorded jumps, touch marker and step controls. A fraction item uses its authored denominator. | Submit the selected location. Starting position alone is ineligible for submission. |
| Numeric add, subtract, compose, digit-value and decimal operations | Add/remove place-value pieces and exchange ten adjacent lower units for one higher unit or split one. Column range follows the given numbers and grade. | Submit the constructed quantity. Edit history and regrouping stay local to the item. |
| Fraction answer, equivalent numerator and fraction comparison | Tap a bar or circle to shade equal parts, adjust partitions or inspect given fractions. Multiwhole items have a whole selector. | Submit the fraction or missing numerator. Comparison retains the original response. Mixed-number entry uses the fraction answer field and subject evaluator. |
| Selected multiplication/division facts, missing factor, rectangle area/perimeter and missing side | A grid of up to 12 rows by 12 columns with tap and row/column controls. | Independent work can count rows, groups or units. The tool does not calculate or submit a product, quotient, area or perimeter. Larger-number work continues through the original response format. |
| Clock and elapsed-time operations, Grade 1/2 length and coin tasks | Move the selected clock hand, compare two markers on a unit ruler, or assemble quarters, dimes, nickels and pennies. | Exploration alongside original entry. The clock face gives no conversion of the question into digital time. Individual denominations are labeled without adding their total. |
| Kindergarten shape composition, Grade 4 angles, other geometry | Place and quarter-turn two triangles. Trace polygon edges/corners, rotate and mark cube faces, try symmetry lines through the centroid, or position an angle ray. Trial markings stay attached to the underlying feature. | Submit the original shape, dimension or angle response. A practice shape is separate from an assessed diagram. |
| Items presenting a chart or line plot | Inspect the original data and mark individual units or observations. | Submit the child’s own comparison or reading. A mark alone changes no attempt evidence. |
| Other numeric, fraction, text or story tasks | Form/choices and contextual tools. Numeric keypad supports digits, decimal, minus, deletion and clear. Fraction mode adds slash and space. Scratchpad supports pencil, eraser, undo, redo and clear. | Keypad edits the same native input at the caret. The subject evaluator handles invalid, equivalent and supported formats. Scratchpad entry is available for non-early Math outside the optional challenge. Sketches and edits are transient. |

The scratchpad creates its grid canvas on first opening and keeps work while collapsed. A finger, stylus or mouse can draw. The shared canvas input helper maps each pointer into this sheet’s 840 × 560 bitmap at full precision. Learning reads only the position. Its history remains in the current activity’s memory. Arrow keys and Enter support a keyboard mark. The latest 64 edits can be undone while older marks remain in memory. Disposing the activity releases the marks and history. | Skill family and examples | Appropriate workspace | Child response and assistance boundary |
| --- | --- | --- |
| Letter recognition, print–picture association, vocabulary, listening directions | Large letter or illustrated choices and a distinct spoken instruction or whole-word stimulus. | Submit the authored choice. A printed target being decoded stays out of the early instruction and image clues. |

| Main idea, supporting detail, inference, theme and viewpoint | Persistent passage alongside choices or explicit selectable evidence if the item supplies eligible spans. | Preserve authored answer and distractor meanings. | Short writing, revision and creative exploration | Comfortable editable text, clear save/check action and a persistent prompt or passage. | Accept authored editing alternatives under the existing validator. Save open writing as exploration. No generated response or automated mastery judgment. |

Vowel-team and punctuation choices preview the completed text. Word, sentence and story boards track duplicate tiles by index and allow removal, reordering and undo. ## Adding and verifying an interaction

1. Name the observable skill, authored givens, available response and assistance boundary. Record the relationship in the appropriate matrix. A new representation must have a reachable answer for every supported item in its range.
2. Select the interaction deterministically from trusted item characteristics and allowed host mode. Define its initial state, bounded edits, neutral default and value serialization. A full solution must never be needed to initialize the child's model.
3. Implement mouse, touch and keyboard actions with a distinct tap alternative for drag. Keep temporary state scoped to one activity. Wire submit, assistance and completion to the current subject attempt and reuse the workspace's focus, narration and feedback paths.
4. Test zero, bounds, repeated input, invalid and equivalent answers, retries and teardown. Exercise the item bank with deterministic fixtures. Test the normal host entrance and a real submitted response. Verify help, heard assistance, a worked example, saving failures and the game return.
5. Include clickable synthetic review cases, before/after renders and the specific evidence limits. Check phone 320×667 and 390×844, tablet 768×1024 and 1024×768, short landscape 844×390, desktop 1366×768 and a larger desktop. Check zoom, touch, focus, fullscreen and reduced motion. Inspect palette, art, diagram labels, clipping and how the primary action is reached.
6. Record the candidate source, build and results in the PR. Physical devices, supervised observations, owner acceptance, hosted TEST, merge and production verification each require their own evidence.
