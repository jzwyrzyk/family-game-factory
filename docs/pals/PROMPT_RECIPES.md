# Gem Pal prompt recipes

Use these internal scaffolds with [STUDIO.md](STUDIO.md), the [design doctrine](DESIGN_DOCTRINE.md), [growth guide](GROWTH_GUIDE.md), and [continuity rules](CONTINUITY.md). Fill them with inspected references and remove irrelevant fields. Use the available image tool's actual attachment and editing requirements; naming a file in prose does not attach it.

## Prepare the request

Resolve the operation and record the target before rendering:

```text
OPERATION: CREATE / GROW / EDIT / EXPRESS
TARGET: character, form, variant, selected reference, revision
PURPOSE: visible useful action and personality contrast
FAMILY ANCHORS: features shared across forms
FORM ANATOMY: body structure, joints, facial construction
GEM SYSTEM: count, relative size, geometry, material, attachment/suspension, function
CHANGE: the observable requested difference
PRESERVE: features that this operation must retain
RENDER: selected Jems finish, lighting, materials, and face language
COMPOSITION: one complete character instance, clear silhouette
BACKGROUND: requested review or production background
EXCLUSIONS: relevant known failure modes
```

Use positive structural directions and a short, concrete exclusion list. Describe what makes the design stronger instead of relying on vague requests for extra polish or complexity. Do not overload a small repair with every rule in the catalog.

Keep labels, lore, arrows, badges, and interface elements outside the individual character image. Use a simple non-character prop only when it makes the action clearer. Preserve a transparent background when required by the actual deliverable.

## CREATE a Base form

```text
Create one original Jems Gem Pal, Base form.
Borrow [mechanism] from [inspiration], reinterpreted as living anatomy.
Its [body structure] enables [action]; its [gem system] performs [function].
Show [material separation and attachment/suspension] clearly.
Convey [temperament and funny limitation] through [pose and face].
Distinguish it from [nearest roster neighbors] through [specific structural differences].
Use selected Jems references for finish, without copying another species' body.
One full-body character. [Background.] [Relevant exclusions.]
```

Make Base satisfying on its own. Establish a future growth premise without reserving all appeal for the later form.

## GROW from the selected Base

```text
Develop Grown from the supplied selected [character] Base reference.
This is the second of two total forms, with one growth transition.
Preserve [specific family identity anchors].
Transform [Base structure] into [Grown structure], with [connected joints and proportions].
Develop [existing gem mechanism] to enable [new visible capability].
Connect the change to [original purpose or personality].
Make the transformation clear at equal display height, retaining structural gems.
Do not substitute larger scale, jewelry, glow, or props for development.
Render one Grown character only, without a Base inset or second pose.
```

Use `mature` as the existing registry key for the display label Grown. If editing an already selected mature image, attach that exact image and explain which reference controls the requested form. Do not blend rejected alternatives into the result.

## EDIT a selected form

```text
Edit the supplied [character / form / revision].
Change [specific delta] to correct [observable issue].
Preserve [face, anatomy, gem topology, materials, palette, pose as applicable].
Make [corrected connection or detail] readable.
Do not import another variant's features or redesign unrelated structures.
One character instance. [Background requirement.]
```

Identify necessary dependent changes before generation. A local defect does not authorize unrelated redesign. A failed render remains an attempt, not a new specification.

## EXPRESS without changing identity

```text
Use the selected [character / form / revision] as the exact identity reference.
Create [expression or reaction] through [facial action and species-specific gesture].
Preserve [face/lens construction, anatomy, gems, supports, proportions, materials].
Communicate [interaction purpose] through [this character's personality].
One character instance with its defining silhouette visible. [Background.]
Do not add limbs, alter gem count, or imply another growth stage.
```

Use the target form's own master. Base expressions do not establish mature anatomy. Preserve intentional suspended gems where they define the character. Treat an unapproved reaction vocabulary as proposed.

## Review the generated result

Apply [QUALITY_GATES.md](QUALITY_GATES.md) to actual pixels and the operation's contract. Record the exact candidate and Pass, Revise, Reject, or Not verified outcomes. Repair obvious anatomy, reference, and composition failures before creative review.

If attempts repeat a defect, refine the specification or reference selection instead of accumulating vague negatives. Preserve unsuccessful attempts and their reasons; never overwrite the selected master silently.
