# Gem Pal Studio

Read [AGENTS.md](../../AGENTS.md), then [the Studio guide](../../docs/pals/STUDIO.md). The canonical rules live in `docs/pals/`; do not duplicate them in this skill or infer approval from this file's existence.

1. Resolve the requested operation: Create, Grow, Edit, Express, Review, Reconcile, or Handoff.
2. Resolve the current character index, relevant owner decisions, exact target form and selected asset. Follow the Studio guide's route when the index is still in the separate artwork PR. Record the source SHA; do not use a dated draft as current without checking.
3. Read [design doctrine](../../docs/pals/DESIGN_DOCTRINE.md) for new concepts, [growth](../../docs/pals/GROWTH_GUIDE.md) for development, [quality gates](../../docs/pals/QUALITY_GATES.md) for image or expression review, and [continuity](../../docs/pals/CONTINUITY.md) for references and feedback. Read only the guides relevant to the task.
4. Inspect actual reference pixels before a faithful image edit. Use the available image tools and their current attachment/editing instructions. If an exact master is unavailable, keep the selection and its gap explicit, complete independent useful work, and ask only for the missing image when the requested edit requires it. Do not substitute or invent an approved asset.
5. Use [prompt recipes](../../docs/pals/PROMPT_RECIPES.md). Preserve the selected form during edits and expressions; allow meaningful anatomical development during growth while retaining family identity. Produce one character per individual profile.
6. Apply the quality gates to actual output before presentation. Keep two total forms and preserve the index's `base` and `mature` keys; Grown is the display name of `mature`. Do not import the old middle form, runtime thresholds, or maker ranks into the art brief.
7. Record the exact candidate, observable check results, owner decision, and affected downstream assets. Keep internal review, art approval, expressions, rig compatibility, integration, and in-game evidence separate.
8. Update the established records and applicable canonical guide within the authorized scope. Run the repository documentation checks for repository edits. Honor existing user authorization; do not create another approval gate for already approved work.

For new missing records, adapt the [empty record template](../../docs/pals/templates/character-record.template.json) to the existing index rather than creating a second registry. Keep technical IDs and review labels out of child-facing art.

Present requested visuals with a concise statement of character/form, what visibly changed, and material unresolved issues. Do not claim measured throughput improvements or model fine-tuning without evidence. This repository skill adds guidance; it does not itself generate assets, merge another feature, alter Project settings, or deploy the application.
